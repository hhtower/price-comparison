# MCP 报价服务

通过 MCP 查询本站商品、商家报价和价格历史。MCP 与 Skill 共用一个接入页面、同一份申请和密钥；已有 Skill 密钥可直接用于 MCP，无需重复申请。

## 申请与使用

1. 从首页「Skill / MCP 接入」进入 `/mcp`，使用邮件验证码登录；新邮箱验证后设置密码完成注册。
2. 登录后填写申请，管理员在后台「Skill / MCP 接入」审核。
3. 审核通过后，在账号内领取密钥。领取页仅显示一次，请及时保存；管理员可在申请详情中按需查看、复制新领取的完整密钥。泄露时应撤销并重新发放。

每次发送或重发邮件前都需完成图形安全验证。未收到邮件时，检查垃圾邮件并等待倒计时后重试，不必重新填写资料。

## 部署配置

更新后先运行 `npm run db:migrate`，再构建并启动 API；无需额外 worker。

领取新密钥前，须在 `.env` 配置 `MCP_KEY_ENCRYPTION_KEY`：32 个随机字节的十六进制值（64 个字符）。可在本地使用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成并安全保存，所有 API 实例使用同一值。此值应随部署密钥备份，不能随意更换，否则已加密保存的密钥将无法查看。

管理员列表按用户逐行显示，点击「详情」审核或管理密钥，再点击「查看完整密钥」按需获取。完整密钥不会随列表返回，也不保存到浏览器存储。重新发放后，需由用户领取新密钥并同步更新客户端配置。

按 `.env.example` 配置 `PUBLIC_SITE_URL` 和 `SMTP_*`。发信服务需支持 TLS，SMTP 账号、密码和发信地址以服务商提供的信息为准。配置修改后重启 API。

邮件服务未配置时暂停邮件验证，已有账号仍可使用密码登录。审核通知失败可在后台重发，也可直接在账号内查看审核结果。

生产环境使用 HTTPS，代理保留鉴权头、Cookie 和 MCP 协议头，并将 `/api/` 转发至 `/v1/`。仅在可信代理覆盖来源地址且 API 禁止绕过时启用 `TRUST_PROXY`。

## 客户端接入

客户端需支持 Streamable HTTP 和自定义请求头：

```text
服务地址：https://你的网站域名/api/mcp
请求头：Authorization: Bearer <领取的密钥>
传输：Streamable HTTP
```

| 工具 | 用途 |
| --- | --- |
| `search_products` | 搜索商品，获取标准商品编号 |
| `get_product_offers` | 按商品编号查询、筛选和分页比较商家报价 |
| `get_price_history` | 查看商品价格历史 |

参数由客户端读取工具定义；使用额度和有效期以审核结果为准，Skill 与 MCP 按同一把密钥合并计算。撤销或重新发放后，两种接入方式都需更新密钥。

报价是采集快照，最终价格与库存以商家为准。比较时核对币种、期限、购买数量和售后条件。

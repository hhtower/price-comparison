## 本项目的使用边界

样本与算法只进入服务端构建。前端仅收到已校验的分数、有限枚举证据与结论，不携带挑战、数字回答或样本库。

独立的“行为一致性”检测已移除。指纹一致性使用上游 nuisance-Hellinger 与 ordered-block 特征融合结果；目标排名第一且未取整概率至少 0.8 才通过。该阈值是本项目的展示判据，不代表经独立验证的假阳性控制。

这些概率在固定候选集中归一化，不能用于证明实际模型来源；库外模型也可能被归到某个候选。请求模型必须精确匹配登记 ID，未覆盖标签/别名显示未测试，不做模糊归属或自一致性兜底。

指纹随机挑战轮数严格使用用户选定的 runs（1–5），不因完整模式或项目最低次数而增加。上游支持 1、2、3 轮校准，多于三轮时沿用三轮校准参数，不声称五轮得到独立校准；算法和参考库不改写。上游算法可忽略不合格回答；本项目在调用前验证每一轮，任一失败即停止并标记风险，避免把失败样本丢弃后仍报告通过。有效数字下限沿用上游规则，完整流中严重不足的数字序列也视为无效响应。原始回答仅保留在本次服务端检测内存中。

## 更新方法

1. 选择明确的上游 commit，核对许可与样本来源；不能用 mock 生成的样本替换正式参考库。
2. 一并更新算法、挑战生成器、数据、声明和本说明，保留完整 MIT 声明。
3. 使用公开参考回答做固定结果回归，验证已登记模型、错误模型、未登记别名、截断、超时和取消路径。不要在测试中调用真实付费模型。
4. 运行质量工具/共享 runtime 测试、受影响 Vitest、typecheck 和 build；确认生产服务可加载库且前端构建不包含库。
5. 模型登记和计分含义变化需同步报告契约与文案，禁止静默用不同库版本混合重测证据。
